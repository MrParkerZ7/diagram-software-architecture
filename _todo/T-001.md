## Context

G-001 draws seven micro-frontend architecture diagrams (CSR, SPA, MPA, SSR, SSG, ISR, RSC) from one shared frame, so the
reader can compare them and see the composition point move. This ticket builds that frame and proves it in two ways:

1. **A dry run.** The full page data of every approach is built on the frame: title, statements, subtitles, cables,
   labels and companions. Both gates pass for each, with no text out of place.

shared by several slots (prompt master `shared/project-types/LIBRARY.md` section 2a, *Where the work about one slot goes*,
and section 2b). When this ticket closes, the frame is **frozen**: T-002 to T-007 use it as it is.

  text, and the icon stays at full colour. `opacityGroup=1` makes the viewer draw the whole card in one
  `<g opacity="0.45">`, icon and fold included.

  elevation and fill):

- **Routing table:** the route (ports and waypoints) is kept per `(from_id, to_id)` pair. The label slide (edge geometry

**Adjacency invariant.** A run-time cable:
- joins adjacent columns, or
- stays inside one container as one straight segment, or
- runs in a street, a gutter or the east lane outside every column.

in free space. No cable crosses a third party's container (WALL-CUT, hard in both profiles), puts a bend inside a

**Row-only README commit** (the one procedure for a commit that adds a `## Storage` row; T-001 uses it first, T-002 to
T-007 by name). Builds run in parallel and each adds its row to `architecture-frontend/README.md`, so the working-tree
README may hold another build's uncommitted row, which a plain `git commit -- <paths>` would commit. Other sessions also
commit to this repo at any moment (board claims), so every step works from one recorded base commit, `<base>`. Run every
line in Git Bash (the Bash tool), each as its own call, with the values written out (shell variables do not carry between
calls). `<paths>` = this commit's other exact paths; `<tmp>` = a new temporary folder outside the repo; `<msg>` = the
message file written in an earlier call. The frame contract names the pre-commit leak check but never copies its
pattern: the pattern holds the words it searches for, so a committed copy would hit the check and the Done-when search.
1. `git rev-parse HEAD` (prints `<base>`); `git show <base>:architecture-frontend/README.md > <tmp>/README.md`; then add
   only this ticket's row to `<tmp>/README.md`, in number order, with LF line endings.
2. `diff -q --strip-trailing-cr <tmp>/README.md architecture-frontend/README.md`
   - **Exit 0** (the working-tree README holds no other build's change): commit it as it is, in one call:
     `diff -q --strip-trailing-cr <tmp>/README.md architecture-frontend/README.md && test "$(git rev-parse HEAD)" = <base> && git add -- <paths> architecture-frontend/README.md && ! <the leak check's staged-lines command, on <paths> architecture-frontend/README.md> && ! <its message command, on <msg>> && git commit -F <msg> -- <paths> architecture-frontend/README.md`.
     If it stops at `diff` or `test`, delete `<tmp>` and start again at step 1. If the leak check prints a hit, fix the
     file and start again at step 1. If it stops at `git commit` itself (a hook failed, or `cannot lock ref 'HEAD'`),
     nothing was committed: fix a hook failure, delete `<tmp>` and start again at step 1.
   - **Exit 1** (another build's uncommitted change is there): commit `<base>`'s README plus this row only, through a
     private index, the built-blob method T-008 step 6 uses in the prompt master:
     1. `git hash-object -w <tmp>/README.md` (prints `<blob>`);
     2. `GIT_INDEX_FILE=<tmp>/index git read-tree <base>`;
     3. `GIT_INDEX_FILE=<tmp>/index git update-index --add --cacheinfo 100644,<blob>,architecture-frontend/README.md`;
     4. `GIT_INDEX_FILE=<tmp>/index git add -- <paths>`;
     5. the pre-commit leak check, both commands: the staged-lines one on `<paths> architecture-frontend/README.md`, with
        `GIT_INDEX_FILE=<tmp>/index` before its `git diff`, and the message one on `<msg>`. On a hit, fix the file, delete
        `<tmp>` and start again at step 1;
     6. `test "$(git rev-parse HEAD)" = <base> && GIT_INDEX_FILE=<tmp>/index git commit -F <msg> && test "$(git rev-parse HEAD~1)" = <base>`.
        - **It stops at the first `test`:** another commit landed since step 1, and nothing was committed. Delete `<tmp>`
          and start again at step 1.
        - **It stops at `git commit` itself** (a hook failed, or `cannot lock ref 'HEAD'`): nothing was committed. Fix a
          hook failure, delete `<tmp>` and start again at step 1.
        - **It stops at the last `test`:** a commit landed in the instant before `git commit`, and the new commit
          (`<sha>`, the short sha `git commit` printed) undoes it. Run
          `test "$(git rev-parse HEAD)" = "$(git rev-parse <sha>)" && git fetch -q origin && ! git merge-base --is-ancestor HEAD origin/main && git reset -q --soft HEAD~1`.
          If it succeeds, the new commit was not published and the branch is back on the other commit: delete `<tmp>`
          and start again at step 1. If it fails (HEAD moved on, the fetch failed, or another session has already pushed
          the new commit), do **not** reset, which would rewrite published history: stop, set `needs-user` naming `<sha>`
          and the commit it undid (a revert is the owner's or that session's decision), and never push.
     7. `git reset -q -- <paths> architecture-frontend/README.md`: the shared index follows the new HEAD for these paths
        only, and the other build's row stays an uncommitted change, for that build to commit itself. It also unstages a
        README another session had staged in the shared index; that is acceptable, because an exit-0 commit takes the
        working-tree file, not the staged one.
- **What it guarantees:** every tree it commits starts from the recorded `<base>`. The exit-1 commit is made only while
  HEAD is `<base>`, and checked after (`HEAD~1` must be `<base>`). The exit-0 commit (`git commit -- <paths>`) adds this
  commit's own paths to the current HEAD. A race restarts it from step 1. In the rare double race, where a commit lands
  inside step 6's single call, the undoing commit is reset only while it is unpublished; if another session has already
  pushed it, the run stops with `needs-user` instead of rewriting history, and the undo stays public until the owner or
  that session reverts it. It never stages or commits another build's file or row, and it touches the shared index
  only for this commit's own paths. The commit runs the repo's hooks like any commit (never `--no-verify`), and it carries the spec and the builder
  together, so the spec-sync hook has nothing to block.

## Edge cases

- **`DIAGRAM_KIT` unset or wrong:** the builder exits non-zero with `DIAGRAM_KIT must point to the prompt master's shared/prompts/3-diagram`; nothing is written.
- **No browser or no draw.io viewer found:** the render helper exits non-zero and names what it looked for (the variable names, never a resolved path). The ticket is not done without a looked-at PNG, so say it and stop. Never report a render that did not run.
- **A glyph in the node table is missing from `CLAY_DEMO`:** stop and file a ticket (`source: build:T-001`). Do not substitute a flat box: the Kit Layer Law forbids it.
- **An approach cannot meet step 4's bar.**
  - A geometry problem is the frame's to fix with step 4's moves: resize or move a container, widen a street, a gutter
    or the east lane, move a bend to other free space, grow the page. It is never handed to the owner.
  - Only when no frame-only change can meet the bar does the fix need a change to a ticket's flow or text: merge two
    cables, drop one, or move a node across columns. Then the frame is **not** frozen: T-001 stays `in-progress`, with
    `decision:` naming the approach, the cable (`<from_id> → <to_id>`) and the finding, and T-002 to T-007 stay blocked.
- **The muted cards' icons still look active in the render:** check that `opacityGroup=1` is on the cell. If the viewer ignores it, stop and file a ticket (`source: build:T-001`); never ship a muted node that reads as active.
- **`draft-analyze _workspace` refuses** (for example, a hand-made `_workspace` already exists): follow its message. A hand-made one with no marker gets the marker written in place.
- **Number 001 already taken:** set `needs-user` and stop (step 5).
- **The spec-sync hook blocks a Stop:** the builder was written or changed without its unit spec. Write or update the spec's sections 3 to 5 in the same turn, then continue (step 0). Never use the hook's override file. If the hook names another slot's builder, that drive is mid-turn: wait and retry; never edit a spec to clear another slot's builder.
