## Context

The third of G-001's seven diagrams. In an MPA, every page is a full HTML document from a server. Micro-frontends split
**by page**:
- path rules send each URL to the server of the team that owns it;
- a link to another team's page is a full page load;
- there is no client shell composing team UIs.

The composition point is the **edge router** (path rules, per request, at page level). This is the pattern Next.js
documents as Multi-Zones: separate applications on one domain, each serving a set of paths, with a hard navigation
between zones and a soft one inside a zone. Labels are in English (Q1).

### Content

- **S1 (HTML):** `On the server of the team that owns the URL, for every page request. Each page is a complete HTML document.`
- **S2 (composed):** `At the edge, per request, page by page: path rules send /catalog/* to team A, /cart/* to team B and /account/* to team C. Pages of different teams are joined only by links. The shared header and footer come from a versioned shared package, or a server-side include.`
