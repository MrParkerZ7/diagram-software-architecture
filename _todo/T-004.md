## Context

The fourth of G-001's seven diagrams. In SSR the HTML is produced on the server for every request. With
micro-frontends, the usual shape is **server-side composition**:
- a page composer fetches an HTML fragment from each team's server, in parallel, with a timeout and a fallback per
  fragment, and returns one page;
- in the browser, each team's JavaScript then hydrates its own fragment.

The composition point is the **page composer** (the origin, per request). Tools that work this way include Podium (a
layout server stitching podlets) and server-side includes. The chat's point: SSR does not share one cached page across
users, so the CDN serves only the static files. Labels are in English (Q1).
