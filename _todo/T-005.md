## Context

The fifth of G-001's seven diagrams. In SSG every page is generated ahead of time, at build, and the CDN serves the
same file to everyone. With micro-frontends, the composition moves to **build time**:
- each team publishes a versioned package;
- an integration build pins those versions, imports every team's package, reads content, and prerenders every page.

This is build-time integration, whose known cost is **lockstep releases**: a team's change reaches users only after
the whole site is rebuilt.

**Islands do not escape that cost by themselves.** Astro "automatically builds and bundles your client-side
JavaScript", so an ordinary island ships with the site build, in lockstep. An island escapes lockstep only if it loads
its team's code from that team's own deployment at run time, which is run-time integration, as in CSR.

**Islands may still call an API at run time.** A shop's Cart team cannot prerender a user's cart, so its island fetches
the cart through the BFF at run time. No server renders HTML at request time: the chat's "a static-only export has no
server, so no BFF" holds for the static site itself, while the BFF here is hosted apart from it, and only islands call
it.

The composition point is the **integration build**. Labels are in English (Q1).
